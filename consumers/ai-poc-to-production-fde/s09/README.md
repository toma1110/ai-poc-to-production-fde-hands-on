## ファイルを準備して記入する

この記入演習はAWSを使わず、受講者のPC上で行います。CloudShellにあるS05の実行記録を使う場合は、先にS05のREADMEに従って記録をPCへ保存してください。CloudShellに保存した実行記録と、これからPCで記入するワークシートは別のものです。

1. PCに `ドキュメント\FDE-case-work` などの作業フォルダーを作ります。上の「架空ケース」と「L02 業務フローと優先課題」をGitHubで開き、それぞれのページの **Raw** を選び、本文をMarkdownファイルとしてこの作業フォルダーへ保存します。ダウンロードした原本は残し、記入用に `l02-working.md` というコピーを作ります。PC上のMarkdown対応エディターでこのコピーを開きます。
2. ケースの「現在の業務（聞き取り前の仮説）」を読んで、L02に流れ、優先課題、質問を書きます。これは顧客へ聞く前の仮説として記録します。S05の技術記録から分かるのは選定ログの記載内容までです。`status=500`、`durationMs=0.07`、`RuntimeError`だけでは根本原因や顧客影響は分からない、と残してください。
3. 編集内容をPCに保存し、ファイルを閉じて `l02-working.md` をもう一度開きます。記入した内容が残っていることを確認します。このファイルをL03/L04の検討と、最後の提案へ引き継ぐ手元の作業記録にします。
4. [L03](l03-workbook.md)と[L04](l04-workbook.md)のRaw本文も同じ作業フォルダーへ保存し、作業用コピーを作って記入します。L04にはS05の保存済み記録を使い、自分の実測と出所が明示された講師の保存済み実行例を区別して書きます。講師例の値を自分の計測値として転記しません。
5. 「L05 顧客提案テンプレート」のリンクを開き、Raw本文を作業フォルダーに保存します。原本は残し、`l05-working.md` というコピーをPC上のMarkdown対応エディターで開きます。L02の優先課題・仮説・質問、L03で比べたAI案と非AI案、PoCで確かめる問い・評価ケース・継続または中止の条件、L04の証拠と限界をつないで、顧客に提案する次の判断を記入します。L02の業務仮説を顧客の確定事実に置き換えず、L03の評価条件を合意済みの基準として書かず、技術例も顧客業務の実績として扱いません。
6. L05をPCに保存して閉じ、もう一度開いて読み返します。主張ごとに根拠の出所、事実／仮定／未確認、限界が対応しているかを確認し、未確認の判断を顧客と決める次の項目に残します。必要な記録を自分の作業フォルダーに保管し、S06/S09で使い終えたことを確かめてから、不要な一時コピーを整理します。

## この演習で使う技術記録

技術例は固定版 [共有アプリ v1.0.2 のREADME](https://github.com/toma1110/aws-observability-sample-app/blob/v1.0.2/README.md) と、[S05 AI調査資料](../s05/README.md)に対応する保存済みの実行記録を使います。アプリのversionとS05資料のcommitは別々の識別子です。ケース資料とL04の証拠表に、確認できた値と測定境界を記載しています。

このL02からL05までのワークシート記入では、保存済みのケースと実行記録を使うため、新たなAWS resourceの作成、AWS呼び出し、Bedrock推論は行いません。このファイル編集手順自体にAWSやBedrockの利用料金は発生しません。共有アプリを別途実行する場合は、この演習資料の記入とは別の作業です。実行条件、料金、cleanupを確認してから、固定版READMEの手順に従ってください。

数値は出所と測定境界を保ち、仮定、未確認事項、実請求額を混同しないでください。講師の実行値を自分の計測値として転記しないでください。
